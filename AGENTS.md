# Foodgram FastAPI — Правила и методология обучения

## 🎓 Контекст проекта и профиль студента
Этот проект — перенос учебного проекта **Foodgram** с **Django (DRF)** на **FastAPI + SQLAlchemy 2.0 (async)**.
Студент отлично знаком с Django и DRF, но изучает FastAPI, асинхронность и современную SQLAlchemy.

---

## 🧭 Методология обучения (ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА ДЛЯ АССИСТЕНТА):

1. **Обязательные параллели с Django:**
   * Всегда сравнивать: «Как это работает в Django/DRF» vs «Как это устроено в FastAPI/SQLAlchemy».
   * Подсвечивать скрытую «магию» Django и показывать, как в FastAPI мы контролируем этот процесс явно.
   * Обращать внимание на тонкости (например, `ondelete` вместо `on_delete`, `from_attributes=True`, `Mapped[str | None]` для nullable-полей, `session.commit()` + `session.refresh()`).

2. **Построение сквозных цепочек запросов (Data Flow):**
   * Объяснять путь запроса от начала и до конца по файлам и слоям:
     `Клиент -> Uvicorn -> main.py -> routers.py -> endpoint -> Pydantic Schema -> Depends -> CRUD -> Security -> SQLAlchemy Model -> DB -> Response Schema`.
   * Показывать, кто за что отвечает и почему архитектура разделена на слои.

3. **Интерактивный формат «Теория -> Задача -> Code Review»:**
   * **НЕ писать весь рабочий код за студента!**
   * Сначала давать объяснение и архитектурную схему.
   * Формулировать практическое задание студенту (написать модель, схему, CRUD или роут).
   * Проводить вдумчивый Code Review написанного кода студента, разбирать нюансы типизации и логики.
   * Тестировать результат реальными запросами через терминал или TestClient.

## 📌 Текущее состояние проекта (Где мы остановились):

1. **База данных и архитектура:**
   * Асинхронное подключение SQLAlchemy 2.0 (`core/db.py`).
   * Миграции Alembic настроены и применены.

2. **Готовые модули:**
   * **Tags** (`/api/tags/`): Модели, схемы, CRUD, эндпоинты (список, получение по id).
   * **Ingredients** (`/api/ingredients/`): Модели, схемы, CRUD, эндпоинты (список с поиском, получение по id).
   * **Users & Subscriptions** (`/api/users/`):
     - Модели `User` и `Subscription` в `app/models/` (с внешними ключами, каскадным удалением, unique и check constraints).
     - Схемы `UserCreate` (с паролем) и `UserResponse` (без пароля) в `app/schemas/user.py`.
     - Безопасность `app/core/security.py`: хеширование `hash_password` и проверка `verify_password` на `bcrypt`.
     - CRUD `app/crud/user.py`: получение по id/email/username и создание пользователя с хешированием.
     - Эндпоинт `POST /api/users/` (регистрация с валидацией уникальности email и username).

## 🚀 Следующий шаг для продолжения обучения:

**Аутентификация и работа с токенами:**
1. Эндпоинт входа в систему **`POST /api/auth/token/login/`**:
   - Принимает `email` и `password`.
   - Проверяет через `verify_password`.
   - Генерирует токен (Djoser-совместимый или JWT) со структурой ответа `{"auth_token": "..."}`.
2. Зависимость **`get_current_user`** через `Depends`:
   - Читает заголовок `Authorization: Token <token>`.
   - Извлекает пользователя из БД или возвращает 401 Unauthorized.
3. Эндпоинты профиля:
   - **`GET /api/users/me/`** (информация о текущем вошедшем пользователе).
   - **`POST /api/auth/token/logout/`** (выход из системы, инвалидация токена).
